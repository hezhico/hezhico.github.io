开张：把写字的地方重新搭一遍

旧的站点是手写的：一个 index.html，四篇文章各占一个 HTML 文件，改一个字要动三个地方。能用，但每写一篇都像在给自己加活。

所以这次换了做法——把内容交给 Markdown，把渲染交给构建工具，把发布交给 Git。

为什么是静态站

博客的负载模型极其简单：读多、写少、几乎不需要登录。这种场景下，动态站点的实时渲染、数据库连接、缓存穿透全都是白付的成本。

静态站把这一切压平成「一堆已经生成好的 HTML 文件」：

  • 首屏不需要等待后端，CDN 边缘直接吐文件
  • 没有数据库，就没有注入、没有连接池、没有备份策略
  • 没有运行时，服务器挂了也不影响已发布的页面

代价也明确：搜索、评论、阅读统计这些需要服务端状态的功能，得另找方案（或者干脆不要）。

为什么是 Astro

选它的核心理由只有一个：默认零客户端 JavaScript。

大多数静态站点生成器会给你一个前端框架的运行时，页面里塞几十 KB 的 hydrate 代码，只为渲染一些本可以静态生成的内容。Astro 反过来——除非你显式声明某个组件需要交互，否则它只输出 HTML 和 CSS。

内容组织用的是 content collections，frontmatter 有类型校验，写错字段构建时直接报错，而不是上线后才发现某篇文章的日期是 undefined。

const posts = defineCollection({
  loader: glob({ pattern: "**/[^_]*.{md,mdx}", base: "./src/content/posts" }),
  schema: z.object({
    title: z.string(),
    pubDatetime: z.date(),
    tags: z.array(z.string()).default(["others"]),
    description: z.string(),
  }),
});

这套站的取舍

维度 选择 理由
渲染 构建期全量生成 内容量小，秒级完成
样式 AstroPaper 主题 + Tailwind 搜索、标签、归档、明暗切换全是现成的
字体 系统字体栈 不请求第三方，中文首屏快
搜索 Pagefind 静态索引 构建时生成，不需要任何服务端
评论 暂不做 想说话会发邮件
发布 构建产物直接推 Git 不依赖 CI，构建在哪跑都一样

一个刻意的设计

第一版我自己手写了整套样式，追求「一种光」：只有页面顶部一层雾霭，没有阴影、没有渐变按钮、没有多余的动效。

好看归好看，但代价是我得自己维护搜索、标签页、明暗切换这些本该一次做完的东西。所以第二版换成了成熟主题——先把功能补齐，再谈审美。排版和留白留给主题的作者，内容留给字。

先这样。往后每写一篇，就往 src/content/posts/ 里扔一个 .md 文件。剩下的，交给构建。
